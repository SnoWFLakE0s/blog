While using my laptop I found a weird problem with the touchscreen seemingly going into a standby state where it would lag on response to a touch input after some duration of time. This was particularly annoying when I wanted to drag, as it would register as clicks instead. This was very annoying to deal with, so while looking for solutions I came across Windows documentation detailing how Windows HID-compliant touchscreens are implemented:
https://learn.microsoft.com/en-us/windows-hardware/design/component-guidelines/touchscreen-power-management

It seems like that the touchscreen driver chip will internally gate inputs. I tracked down the touchscreen in device manager ("HID-compliant touch screen") and looked at its parent, which appeared as as the I2C HID Device on ACPI\ELAN2513. I did try turning off the power management option there, but after some testing it seemed like the issue was still there. The I2C Device itself under Human Interface Devices itself was parented to the Intel Serial IO I2C Controller - 7E79 under System Devices. I checked the children on this device and it returned only ACPI\ELAN2513. Disabling the sleep function on this seems to fix the problem of the internal gating causing touch display lag!
